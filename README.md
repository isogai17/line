# わたしの家計簿

旧「ことばの下書き」を、個人専用の家計簿Webアプリへ変更しました。同じRenderサービス・公開URLを使えます。LINE自動返信・OpenAI API呼び出しはありません。

## できること

- スマホ・PCのレスポンシブ画面。日付は日本時間の今日、初期値は支出。金額・カテゴリ・任意メモで入力。
- 月ごとの収入・支出・収支とカテゴリ別円グラフ。収支は口座残高ではありません。
- 記録の検索、修正、再入力、ゴミ箱への移動と復元。別端末の変更との競合を検出。
- メール本文、文字入りPDF、CSV、xlsx、旧Web家計簿のJSONから候補を作り、確認した明細だけ登録。
- CSV、Excel4シート、全期間JSONバックアップを出力。
- 事業・副業と医療費用の任意項目。申告の補助資料で、税務上の該当性・控除額は判定しません。
- ホーム画面へ追加して独立した画面で開けるPWA。オフライン保存・バックグラウンド取得はありません。

## 保存方式とプライバシー

クラウド版はRenderのサーバーから外部PostgreSQLに保存します。ブラウザー内だけの保存とは異なります。同じ利用パスワードで開く人は同じ家計簿を閲覧できるため、パスワードは共有しないでください。複数ユーザー向けサービスではありません。

接続情報とパスワードはサーバー側の環境変数だけで保持します。CookieはHttpOnly/SameSite=Strict、HTTPSではSecure。更新操作はOrigin検証、ログイン回数制限、入力検証、パラメーター付きSQLを使用します。API・金融データ・ファイルはブラウザーキャッシュやService Workerへ保存しません。ログイン状態はDBにトークンのハッシュだけを保存するため、再起動後も有効期間内は利用できます。7日経過・パスワード変更後は再ログインが必要です。

クラウドでDATABASE_URLが空なら、保存不能のセットアップ画面になります。一時ディスクへ保存したふりはしません。ローカル確認時だけSQLiteに保存します。ログ・ソース・Gitへ家計簿の記録を保存しません。

## ローカルで試す

Node.js 24.16以上を使用します。

```sh
npm ci --ignore-scripts
npm test
npm start
```

`http://127.0.0.1:3000/` で開きます。このPCの `data/budget.sqlite` に保存されます。必要なら `.env.example` を `.env` にコピーして設定します。既存の `.env` は上書きしないでください。`APP_PASSWORD` を設定すればローカルもログイン必須になります。

## スマホ・PCで同じデータを使う

[公開・切替手順](DEPLOY.md)に従い、今のRenderにPostgreSQL接続文字列を追加します。新しい有料サービスや銀行連携を勝手に作成する必要はありません。

## 取り込み

アップロードしたファイルは、アプリのサーバーメモリー内で読み取り、原本ファイルは保存しません。10MB・500明細、PDFは30ページまで。スキャンPDF・写真のOCR、暗号化ファイル、xls/xlsmの直接取り込みには未対応です。メール本文は「合計」「ご利用金額」などを優先しますが、複数回の合計や税込・税抜の取り違えはあり得るため必ず原本と確認してください。

CSV/Excelは見出し「日付・収支・カテゴリ・金額」が基本です。カテゴリには独自名も使えます。文字コードはUTF-8とShift_JIS、CSVの引用符・改行に対応します。旧Excelで「帳簿明細」を出力すると取り込めます。複数シートのExcelは帳簿明細を優先し、資料シートを重複登録しません。旧ブックで日付が空欄の行は確認画面で補完してください。勝手に月初の日付を補いません。

同じ日付・収支・カテゴリ・金額・メモ、または同じ取込元IDは重複候補として除外します。同日に同額の正当な取引が複数ある場合は、個別入力で登録できます。取り込み後の修正は通常の編集画面を使います。原本は手元で保管してください。金融データの自動取引連携・Gmailの定期取得は未接続です。

## 出力とe-Tax

Excelは帳簿明細・月別集計・事業副業資料・医療費資料の4シートです。数値は数値型、日付は日付型です。CSVはUTF-8 BOM付きで表計算ソフトの数式実行につながる先頭文字を無害化します。CSV・Excelは選択年、JSONは全期間です。ゴミ箱の記録は出力しません。JSON復元は取込確認画面を経由し、既存記録を削除・上書きしません。ゴミ箱の復元は元の画面で行ってください。

Web版のExcel/CSVは申告書やe-Taxの直接読込データではありません。仕訳の借方・貸方、貸借対照表、青色申告決算書は生成しません。医療費の公式フォーム出力は既存のExcel版に残しています。元のExcelデータはWebや外部DBへ自動送信しません。

## バックアップ・運用

- 定期的に「取込・出力」から全期間JSONと必要年のExcelを保存してください。
- 無料Renderは待機後の起動に時間がかかります。再起動・再デプロイしても外部PostgreSQLの記録は残ります。
- DBの容量、無料枠、復元可能期間を確認してください。無料枠は永久の利用保証ではありません。
- 共有端末ではログアウト。ダウンロード済みの帳簿ファイルは利用者が管理してください。
- 通信失敗時は保存完了と表示しません。フォームを残したまま再試行できます。同じIDの再送は重複登録されません。

## 検証

`npm test` は認証、CSRF、金額・日付、集計、登録と再送、競合、ゴミ箱復元、ローカルDB再接続、CSV/Excel、取込の確認と重複を検証します。クラウドDBへの実接続・公開URLでの端末間同期は、DATABASE_URLを設定した後の別途確認が必要です。実際の家計簿はテストデータに使いません。
