# ことばの下書き — AI返信アシスタント

LINEなどで受け取った文章をWeb画面に貼り付けると、日本語の返信案を3つ作成します。「自然に・丁寧に・短く・親しく・断りたい」から選び、その場で編集してコピーできます。

**LINE公式アカウントやLINE Developersの登録は不要です。** LINEへの自動送信や個人チャットの読み取りは行わず、コピーした返信案を自分で元のチャットへ貼り付けて送ります。

## まず試す

Node.js 24以上を使用します。外部npmパッケージは不要です。

```sh
cd /workspace/line
npm ci
npm test
npm start
```

ローカルのポート3000でWebアプリが起動します。初期状態では`127.0.0.1`のみで待ち受けるため、同じPCのブラウザーで使用します。クラウド環境のプレビュー機能は前提にしていません。

**APIキー未設定の場合は、画面に明示されたサンプルモードになります。** 文体別の固定例文を表示し、入力文に合わせたAI生成や外部通信は行いません。`npm run demo`ならキーが設定済みでもサンプルモードを使用できます。

## 実際のAI生成を使う

1. OpenAI APIキーを用意します。ChatGPTの契約とは別にAPI料金が発生します。
2. `.env.example`を`.env`へコピーします。既存の`.env`は上書きしないでください。
3. 自分のエディターで`.env`の`OPENAI_API_KEY`を設定し、`npm start`で再起動します。
4. 画面に「AI返信アシスタント」と表示されることを確認し、テスト用の文章を入力します。内容に応じた3つの返信案が表示されることまで確認してください。

```sh
cp -n .env.example .env
# .envを自分のエディターで編集。キーはGitやチャットに貼らないでください。
npm start
```

APIキーはサーバー側だけで使用し、ブラウザーに渡しません。利用先の環境で変数名が予約されている場合は、そのプラットフォームの正式なシークレット設定方法を使用してください。

| 環境変数 | 用途 |
| --- | --- |
| `OPENAI_API_KEY` | AI生成に必要。空欄ならサンプルモード |
| `OPENAI_MODEL` | 初期値`gpt-4.1-mini`。Responses APIの構造化出力対応モデル |
| `PORT` | 初期値`3000` |
| `HOST` | 初期値`127.0.0.1`。ホストへ公開する場合は`0.0.0.0`などを指定 |
| `APP_PASSWORD` | 利用パスワード。12文字以上。ローカルは任意、外部公開時は必須 |
| `APP_ORIGIN` | 外部公開時に必須。パスなしのHTTPS公開URL（例：`https://reply.example.com`） |

`APP_PASSWORD`はAIのAPIキーとは別に設定する、このアプリ専用のパスワードです。

## スマートフォンから使うための公開

APIキーの作成からHTTPS公開まで、[Render向けの具体的な手順](DEPLOY.md)を用意しています。同梱の`render.yaml`を使う場合、公開URLはRenderが自動設定します。

Node.jsのプロセスを常時実行できるホストか、Docker対応ホストに配置します。実際のホスティング契約や公開は別途必要です。

1. HTTPSの公開URLを用意します。TLS終端はホスティング先・リバースプロキシで行います。
2. ホストの安全な設定画面から`OPENAI_API_KEY`、`HOST=0.0.0.0`、12文字以上の`APP_PASSWORD`、公開先に一致する`APP_ORIGIN`を設定します。
3. `npm ci`で準備し、`npm start`で起動します。Dockerの場合は同梱の`Dockerfile`を使用し、環境変数を実行時に渡します。
4. スマートフォンで公開URLを開き、利用パスワードでログインします。生成→編集→コピー→LINEに貼り付けを確認します。

アプリが必要とする外部接続先は`api.openai.com`のみです。ホストのヘッダーとブラウザーのオリジンを維持して転送してください。サブディレクトリへの配置は対応していません。

外部公開でパスワードやHTTPSのURLが未設定なら起動しません。Dockerでは`HOST=0.0.0.0`を明示的に設定してください。`APP_ORIGIN`やキーなどを変更したら再起動が必要です。

## 使い方

1. 相手から届いた文章を貼り付けます（最大3,000文字）。
2. 返信の雰囲気を選び、「返信案を作る」を押します。
3. 3案から選び、必要なら返信本文を直接編集します。
4. 「コピー」を押して、LINEなど元のチャットへ貼り付け、自分で送信します。

作成中は中止できます。「クリア」で入力と返信案を消去できます。入力や文体を変更すると古い返信案は消去されます。コピーできない環境では本文を選択し、手動でコピーしてください。

## データと運用

- AI生成時は入力文をOpenAI APIに送信します。共有したくない個人情報や秘密は取り除いてください。OpenAIには`store: false`を指定しますが、サービス側のすべてのログがゼロになる保証ではありません。
- アプリは入力・返信案をファイル、DB、ブラウザーのストレージに保存しません。本文、パスワード、APIキー、API応答本文もログに出しません。処理中の文章はメモリに、コピーした内容は端末のクリップボードに残ります。
- パスワードを設定した場合、12時間のHttpOnly・SameSite=Strict Cookieでログイン状態を管理します。HTTPS公開時はSecure属性も付きます。ログアウト・期限切れ・サーバー再起動で再ログインが必要になります。
- AI接続は15秒でタイムアウトし、利用者が作成を中止したり接続を切った場合も中止を要求します。中止前にAIが処理した分の料金が発生する場合があります。
- 少人数向けの構成です。サーバー全体で生成は1分あたり20回・同時2回、ログイン試行は1分あたり10回までです。これらとセッションはメモリ内管理なので、再起動でリセットされます。単一プロセスで運用してください。
- AIは予定や意図を誤解する場合があります。送信前に必ず確認してください。OpenAI APIとホスティングの費用・利用上限は別途管理してください。

## 開発・確認

```sh
npm run dev   # .envを読み込み、変更時に再起動
npm test      # APIキー不要。ローカルHTTPと外部APIのテスト用応答で検証
```

`GET /healthz`は`status: ok`と`mode: sample`または`ai`を返します。これは起動確認で、外部APIの認証成功を保証しません。実際のAIでの生成確認は有効なAPIキーで行ってください。

構成：`src/config.js`が環境設定、`src/server.js`が起動、`src/app.js`がHTTP・認証・回数制限、`src/replies.js`が返信生成、`public/`がスマートフォン対応の画面です。
